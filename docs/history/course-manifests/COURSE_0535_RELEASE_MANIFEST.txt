EduTeX 0.5.35 - Normalized per-check status

Scope
- Add an additive status field to every completed check entry in the JSON report.
- Emit status=passed when the existing passed boolean is true.
- Emit status=failed when the existing passed boolean is false.
- Preserve the existing passed boolean as the backward-compatible authority.
- Preserve report identity, timing, summary metrics, failed-check identifiers,
  diagnostics, catalog, check ordering, outcome semantics, text output, and exit
  codes.
- Add focused assertions for passed and failed check entries.
- Document the normalized status contract in QL-013.

Changed files
- tools/quality_check.py
  - Added additive status to each report check entry.
- tests/test_quality_check.py
  - Added passed/failed status assertions.
- docs/quality_process_spec.md
  - Documented per-check status semantics in QL-013.

Compatibility
- edutex.quality-baseline.v1 remains unchanged.
- Existing per-check passed boolean remains unchanged.
- Existing report fields and outcome semantics remain available.
- No new runtime dependency or CLI option was added.
- Human-readable output and exit-code behavior remain unchanged.
